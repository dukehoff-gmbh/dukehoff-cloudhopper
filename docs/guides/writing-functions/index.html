Writing Functions

With Cloudhopper you write plain Java methods and describe them with a few annotations. You never implement a cloud-specific interface: the annotation processor reads your annotations at compile time and generates the provider-specific handler and deployment artifacts for you.

A function is just a method annotated with @Function plus a trigger:

public class HelloFunction {

    @Function(name = "hello")
    @HttpTrigger(method = "GET", path = "/hello/{name}",
                 summary = "Say Hello", description = "Returns a friendly greeting")
    public String handleRequest(@PathParam String name) {
        return "hello " + name;
    }
}

@Function​

Marks a method as a deployable function and carries provider-neutral deployment metadata. Only name is required.

Which target applies which attribute is listed in the support matrix.

AttributeTypeDefaultDescription
nameString—Unique function name in the deployment target
memoryint128Memory limit in MB
timeoutint30Maximum run time in seconds
minInstancesint0Instances kept warm to reduce cold starts. GCP sets min_instance_count; warm instances are billed while idle. Not applied on the other targets yet (AWS: #48)
identityStringown identityThe identity the function runs as and its permissions are granted to (see Identities and permissions)
extensions@Extension[]{}Vendor-specific attributes (see Vendor extensions)
@Function(name = "resize", memory = 512, timeout = 60)

Triggers​

Trigger annotations decide how a function is invoked. A function may carry several, and Cloudhopper generates each of them; the compatibility tests cover each trigger on its own, so prefer one trigger per function. Without a trigger it can only be invoked directly, as far as the target allows; the support matrix lists what each target offers.

@HttpTrigger​

Exposes the function through an HTTP API gateway.

AttributeDescription
methodHTTP method, e.g. "GET", "POST"
pathRoute, may contain path variables, e.g. /player/{id}
operationIdOperation id used in the generated OpenAPI document
summary / descriptionHuman-readable API metadata; written into the OpenAPI description of the API Gateway on GCP, ignored by the other targets

@ScheduledTrigger​

Invokes the function on a cron schedule. Scheduled functions usually take no parameters and return void.

AttributeDefaultDescription
cron— (required)Cron expression, e.g. "0 0 * * *"
timezone"UTC"Timezone the schedule is evaluated in
@Function(name = "nightlyCleanup")
@ScheduledTrigger(cron = "0 0 * * *", timezone = "UTC")
public void cleanup() {
    // ...
}
TargetScheduleNotes
aws-terraformEventBridge ruleEvaluated in UTC
azure-terraformTimer triggerEvaluated in UTC
gcp-terraformCloud Scheduler jobEvaluates timezone
springboot-httpSpring @Scheduled in the service, and POST /schedules/<function name>Evaluates timezone; see below
knativePingSource that calls POST /schedules/<function name>Evaluates timezone; fires once, also when the service is scaled to zero
scaleway-terraformCron trigger that calls POST /schedules/<function name>Evaluates timezone; fires once, also when the container is scaled to zero

On Spring Boot every running instance fires the schedule on its own. That is right for a single instance. When the service runs with several replicas, or on a platform that scales to zero, set cloudhopper.schedules.in-process=false and let an external scheduler call POST /schedules/<function name> instead, for example a Kubernetes CronJob or the platform's cron trigger. Set cloudhopper.schedules.endpoint=false to switch the endpoints off.

@EventTrigger​

Invokes the function once for each event from a queue or a storage bucket.

AttributeDefaultDescription
source— (required)EventSource.QUEUE or EventSource.STORAGE
name— (required)Name of the queue or bucket: 3 to 63 lowercase letters, digits and single hyphens, starting with a letter
createtruetrue creates the queue or bucket with the function; false connects to an existing one of that name (AWS and GCP; the other targets ignore it)

Delivery is at least once: when the function throws, the platform delivers the event again, so make the function tolerate duplicates. A parameter of type EventMetadata gives you the event id, source, time, delivery attempt and attributes; on invocations that are not events it is null.

Queues​

For EventSource.QUEUE, the message body is deserialized from JSON into the body parameter, just like an HTTP request body.

@Function(name = "orderReceived")
@EventTrigger(source = EventSource.QUEUE, name = "orders")
public void onOrder(Order order, EventMetadata meta) {
    // ...
}
TargetQueueNotes
aws-terraformSQS queueOne message per invocation; failed messages are reported individually and delivered again
azure-terraformStorage queue in the function app's storage accountMessages must be Base64-encoded; after five failed attempts a message moves to <name>-poison
gcp-terraformPub/Sub topic, delivered through EventarcRequires the Eventarc and Pub/Sub APIs in the project
springboot-httpPOST /events/<function name>, or a Kafka topicThe body is the message; optional ce-id, ce-source and ce-time headers (CloudEvents) fill the metadata. Answers 204, or an error status if the function throws. With spring-boot-starter-kafka and cloudhopper.events.broker=kafka, the function consumes the topic <name>; after five failed attempts a message moves to <name>.DLT, see Queues from Kafka
knativeKafka topic <name>, delivered by a KafkaSourceDelivered again up to four times with exponential backoff, then written to <name>.DLT; see Knative
scaleway-terraformScaleway Queue (SQS) <name> with a triggerCalled up to four times per receive, then moved to <name>-dlq after queue_max_receive_count receives (default 1); see Scaleway

Storage buckets​

For EventSource.STORAGE, the function is invoked for every object created or overwritten in the bucket. Its body parameter, if it has one, must be a StorageEvent: bucket, key and size of the object. The function reads the content itself if it needs it, with the storage client of the platform.

@Function(name = "invoiceUploaded")
@EventTrigger(source = EventSource.STORAGE, name = "acme-invoices")
public void onUpload(StorageEvent event) {
    // event.getBucket(), event.getKey(), event.getSize()
}
TargetBucketNotes
aws-terraformS3 bucket with an event notificationThe bucket is named <cloudhopper_name_prefix><name>. S3 keeps one notification configuration per bucket: with create = false, it replaces the notifications the bucket already has
azure-terraformBlob container in the function app's storage accountEvent Grid puts the events on the storage queue <name>-events, which the function reads
gcp-terraformCloud Storage bucket in gcp_region, delivered through EventarcRequires two one-time IAM grants, see Storage triggers
springboot-httpPOST /events/<function name>The body is {"bucket": ..., "key": ..., "size": ...}; bucket defaults to the name in the annotation
knativePOST /events/<function name>No storage source is generated; a CloudEvents sender, for example an S3-compatible store's webhook notification, posts the body {"bucket": ..., "key": ..., "size": ...}
scaleway-terraformPOST /events/<function name>Scaleway has no trigger for Object Storage events; post the body {"bucket": ..., "key": ..., "size": ...} yourself

Bucket names on AWS and GCP are global across all accounts, so choose one that nobody else uses, for example one starting with your company name. Terraform does not delete a bucket that still contains objects.

When a target does not support something​

Not every target supports every trigger or attribute. AWS and Azure ignore the timezone of a schedule, for example. When you compile for a target, Cloudhopper reports what that target ignores:

[WARNING] NightlyCleanup.java:[24,48] Attribute 'timezone' of @ScheduledTrigger is not supported by generator 'aws-terraform'; it is ignored for this target.
[WARNING] ReportMemoryFunction.java:[32,40] Attribute 'memory' of @Function is not supported by generator 'azure-terraform'; it is ignored for this target.

A target can also support an attribute only for some values, such as the source of an @EventTrigger. A value it does not support is reported the same way, for example @EventTrigger(source = TOPIC) is not supported by generator '…'; it supports QUEUE, STORAGE.

To fail the build instead, pass the processor option -Acloudhopper.strictFeatureCheck=true (a compilerArgs entry of the maven-compiler-plugin). Vendor extensions are never reported, since they are meant for one target. Maven shows these warnings only with showWarnings enabled, which is the default from maven-compiler-plugin 3.13.0 on and set in projects generated by the archetype.

Binding request data​

Declare exactly the parameters your method needs and annotate them. The processor deserializes and converts each value to the parameter's declared type before calling your method.

AnnotationBinds toNotes
@RequestBodyThe deserialized request bodyAt most one per method
@PathParam("id")A path template variableBlank value → the parameter name is used
@QueryParam("q")A query string parameterBlank value → the parameter name is used
@HeaderParam("X-Token")An HTTP request headerThe header name is required and matched case-insensitively
@ConfigProperty(name = "report.bucket")A configuration value of the deploymentSee Configuration

Because a blank value falls back to the parameter name, @PathParam Integer id binds the {id} path variable without repeating the name.

Path, query and header values can be bound as String, Integer, Long, Double or Boolean (or the primitive types); they are converted for you.

A parameter of type HandlerContext is recognized automatically — no annotation needed — and gives you invocation metadata (request id, remaining time, memory limit, and so on). The same holds for EventMetadata in event-triggered functions (see @EventTrigger). Any other unannotated parameter is treated as the request body.

@Function(name = "updatePlayer")
@HttpTrigger(method = "PUT", path = "/player/{id}")
public Player update(@RequestBody Player input,
                     @PathParam Integer id,
                     @QueryParam("dryRun") boolean dryRun,
                     HandlerContext context) {
    // ...
}

The method's return value becomes the response body, as JSON with status 200. Body and return value can be parameterized types such as Map<String, List<String>>. Other statuses and response headers are described in Responses.

A method may declare checked exceptions (throws IOException). Any exception the method throws fails the invocation: an HTTP call answers with a server error (see Responses), an event is redelivered. Checked exceptions reach the platform wrapped in FunctionException, runtime exceptions unchanged.

Responses​

An HTTP function answers the same way on every target:

The functionStatusBody
returns a value200the value as JSON
returns an HttpResponse<T>its status, with its headersits body as JSON, or none
throws HttpStatusExceptionits status (400 to 599), with its headers{"error": "<message>"}
throws any other exception500{"error": "Internal Server Error"}
receives a body that is not valid JSON for its input type400{"error": "Invalid request body"}

Return HttpResponse (package eu.cloudhopper.mc.runtime) for a status other than 200 or for response headers, and throw HttpStatusException for client errors:

@Function(name = "getItem")
@HttpTrigger(method = "GET", path = "/items/{id}")
public HttpResponse<Item> get(@PathParam("id") String id) {
    Item item = items.find(id)
            .orElseThrow(() -> new HttpStatusException(404, "no such item"));
    return HttpResponse.ok(item).header("Cache-Control", "max-age=60");
}

@Function(name = "createItem")
@HttpTrigger(method = "POST", path = "/items")
public HttpResponse<Item> create(@RequestBody Item item,
                                 @HeaderParam("Authorization") String authorization) {
    if (authorization == null) {
        throw new HttpStatusException(401, "missing token").header("WWW-Authenticate", "Bearer");
    }
    Item created = items.add(item);
    return HttpResponse.status(201, created).header("Location", "/items/" + created.id());
}
  • HttpResponse.ok(body), HttpResponse.status(status, body), HttpResponse.status(status) and HttpResponse.noContent() (204) create a response; header(name, value) returns a copy with the header. Header names are case-insensitive.
  • The body is sent as JSON with Content-Type: application/json. With a Content-Type header of another media type and a String body, the body is sent as it is, e.g. HttpResponse.ok(csv).header("Content-Type", "text/csv").
  • The message of an HttpStatusException goes to the client; keep internal details out of it. Any other exception is logged with its stack trace, and the client gets no details.
  • On AWS, every response also carries Access-Control-Allow-Origin: *.

Authentication​

A route that only signed-in users of an OpenID Connect provider (Amazon Cognito, Microsoft Entra ID, Google, Auth0, Keycloak, …) may call declares authenticated = true; scopes additionally requires scopes of the token. The function reads the caller's claims with @ClaimParam or a Claims parameter:

@Function(name = "listItems")
@HttpTrigger(method = "GET", path = "/items", authenticated = true, scopes = {"items:read"})
public List<Item> list(@ClaimParam("sub") String userId, Claims claims) {
    String tenant = claims.getString("custom:tenant");
    // ...
}

The client sends Authorization: Bearer <JWT>. Before the function is called, the generated handler verifies the token, the same way on every target:

The requestStatus
has no bearer token401 with WWW-Authenticate: Bearer
has a token that is not valid: signature, issuer, audience, expiry401 with WWW-Authenticate: Bearer error="invalid_token"
has a valid token without one of the scopes403
has a valid tokenthe function is called

The provider is configured once per deployment, with configuration properties (for example in the Terraform variable cloudhopper_config):

Property
cloudhopper.auth.issuerrequired: the issuer, exactly as in the tokens' iss claim, e.g. https://cognito-idp.eu-central-1.amazonaws.com/eu-central-1_AbC123
cloudhopper.auth.audiencerequired: the expected aud claim; for access tokens of Amazon Cognito, which have none, the app client ID in client_id
cloudhopper.auth.jwks-urithe address of the provider's key set; by default the jwks_uri of <issuer>/.well-known/openid-configuration
cloudhopper.auth.jwksthe key set itself as JSON, or Base64-encoded JSON, for providers the functions cannot reach; then nothing is fetched
cloudhopper.auth.required-claimsclaims every token must have, as name=value pairs separated by commas; a list claim must contain the value. For Amazon Cognito, token_use=access refuses the ID tokens of the same app client, which carry the client ID as aud
cloudhopper_config = {
  "cloudhopper.auth.issuer"   = "https://cognito-idp.eu-central-1.amazonaws.com/eu-central-1_AbC123"
  "cloudhopper.auth.audience" = "4m2fv0example"
}
  • Tokens are signed JWTs with RS256, RS384, RS512, ES256, ES384 or ES512. Unsigned tokens, tokens signed with a shared secret (HS256) and RSA keys shorter than 2048 bits are refused. exp is required; exp and nbf allow a minute of clock skew.
  • The key set is fetched on the first authenticated request of an instance and kept for an hour; a token with an unknown key ID fetches it again, at most every 30 seconds. The discovery document and the key set are fetched over HTTPS, unless cloudhopper.auth.jwks-uri names another address.
  • Scopes are read from the scope claim (separated by spaces) and the scp claim (Microsoft Entra ID).
  • @ClaimParam binds String, Long, Integer, Double, Boolean or List<String>; a claim the token does not have is null. Claims reads any claim, e.g. getSubject(), getString("email"), getStringList("groups").
  • The reason a token was refused goes to the log, not to the client.
  • The check runs in the function, on every target. A deployment with an authenticated route needs cloudhopper.auth.issuer and cloudhopper.auth.audience; on AWS and GCP, Terraform refuses to plan without them.
  • On AWS, API Gateway checks the token as well, with a JWT authorizer, so refused requests do not invoke the function: they are answered by API Gateway with the same status codes and the body {"message":"Unauthorized"} or {"message":"Forbidden"}. API Gateway reads the key set from <issuer>/.well-known/openid-configuration, so the authorizer is created only when cloudhopper.auth.issuer and cloudhopper.auth.audience are set in cloudhopper_config (or cloudhopper_extra_config) and neither cloudhopper.auth.jwks-uri nor cloudhopper.auth.jwks is set. The Terraform variable cloudhopper_api_jwt_authorizer = false turns it off.

Sending messages​

A function sends messages to a queue through a Publisher parameter annotated with @Queue. A typical use is fanning out work: a scheduled function sends one message per item, and a queue-triggered function processes each of them.

@Function(name = "startCollection")
@ScheduledTrigger(cron = "0 4 * * *")
public void start(@Queue(name = "collect") Publisher<CollectRequest> queue) {
    queue.sendAll(accounts().stream().map(CollectRequest::new).toList());
}

@Function(name = "collectOne")
@EventTrigger(source = EventSource.QUEUE, name = "collect")
public void collect(CollectRequest request) {
    // ...
}
  • @Queue(name) refers to a queue that an @EventTrigger(source = QUEUE) of the same project creates. The generator uses its deployed name, gives the sending function's identity permission to send to exactly this queue, and passes the queue's address to the runtime.
  • A queue that another system owns is declared with @Queue(name = "...", existing = true); it is used under exactly this name.
  • A @Queue that is neither is a build error, so messages cannot end up in a queue nobody reads.
  • A String is sent as it is, any other message as JSON, the way queue triggers read their input; the consumer receives the message as its input type.
  • sendAll sends in as few requests as the queue's batch limits allow. If the queue does not accept a message after retries, send and sendAll throw PublishException.

The target needs a runtime module for this, which the archetype adds; if it is missing, the build names the dependency. Which targets support @Queue is listed in the support matrix.

Cloudhopper sends with small HTTP clients of its own instead of the cloud SDKs (SQS on AWS and Scaleway, Pub/Sub on GCP, Storage queues on Azure; Kafka on Knative uses the Kafka client of Spring): the SQS client of the AWS SDK alone would more than double the size of a function's runtime and its cold start, and SDKs often conflict with the dependencies of the project. The cloud APIs these clients call are stable and versioned. An implementation based on an SDK can replace them through the eu.cloudhopper.mc.runtime.spi.PublisherFactory service interface.

Reading and writing buckets​

A function reads and writes objects in a bucket through a BlobStore parameter annotated with @Bucket:

@Function(name = "renderReport")
@EventTrigger(source = EventSource.QUEUE, name = "reports")
public void render(ReportRequest request,
                   @Bucket(name = "acme-reports", access = Bucket.Access.WRITE) BlobStore reports) {
    reports.put(request.id() + ".csv", csv(request), "text/csv");
}

@Function(name = "downloadReport")
@HttpTrigger(path = "/reports/{id}", method = "GET")
public String download(@PathParam("id") String id,
                       @Bucket(name = "acme-reports") BlobStore reports) {
    return reports.get(id + ".csv")
            .map(content -> new String(content, StandardCharsets.UTF_8))
            .orElse("");
}
  • get(key) returns the content, or an empty Optional if there is no such object; put(key, content, contentType) creates or replaces an object; delete(key) removes it; list(prefix) returns the keys that start with the prefix.
  • access is READ (the default), WRITE or READ_WRITE. The runtime refuses every operation the parameter did not declare with BlobAccessDeniedException, on every target. On AWS and GCP, the generator also gives the function's identity exactly these permissions on this bucket; on Azure, Scaleway and Knative the key of the storage applies to all functions. Other failures throw BlobStoreException.
  • The generator creates the bucket once per name (on AWS and Scaleway named <cloudhopper_name_prefix><name>, on Azure a blob container in the function app's storage account). On Knative the buckets must exist; see Knative. If a storage trigger of the project has the same name, both use its bucket. A bucket that another system owns is declared with @Bucket(name = "...", existing = true) and used under exactly this name; all @Bucket parameters of one name must agree on existing.
  • A bucket that your own Terraform creates goes into the local cloudhopper_bucket_names; see Values from your own Terraform.
  • Bucket names on AWS and GCP are global across all accounts, on Scaleway within a region. Use 3 to 63 lowercase letters, digits and hyphens, unless the bucket is existing.

The target needs a runtime module for this, which the archetype adds; if it is missing, the build names the dependency. Like the publishers, the stores call the storage APIs with small HTTP clients of their own instead of the cloud SDKs; an implementation based on an SDK can replace them through the eu.cloudhopper.mc.runtime.spi.BlobStoreFactory service interface. Which targets support @Bucket is listed in the support matrix.

Reading and writing tables​

A function reads and writes items of a key-value table through a KeyValueStore parameter annotated with @Table:

@Function(name = "registerAccount")
@HttpTrigger(path = "/accounts/{id}", method = "PUT")
public String register(@PathParam("id") String id, Account account,
                       @Table(name = "accounts", access = Table.Access.READ_WRITE) KeyValueStore accounts) {
    Key key = new Key("account:" + id, "profile");
    boolean created = accounts.putIfAbsent(new Item(key, Map.of("name", account.name(), "logins", 0L)));
    return created ? "created" : "exists";
}

@Function(name = "listOrders")
@HttpTrigger(path = "/accounts/{id}/orders", method = "GET")
public List<Map<String, Object>> orders(@PathParam("id") String id,
                                        @Table(name = "accounts") KeyValueStore accounts) {
    return accounts.query("account:" + id, "order:").stream().map(Item::attributes).toList();
}
  • An item has a key of a partition and a sort key, and attributes. query(partition, sortKeyPrefix) reads the items of one partition whose sort keys start with a prefix, in the order of their sort keys; query(partition, prefix, limit, pageToken) reads them page by page. There are no queries across partitions and no secondary indexes: to list items of several partitions, keep an index partition of your own.
  • get, put, delete; putIfAbsent creates an item only if there is none with its key; update(key, set, expected) changes attributes of an existing item only if its attributes have the expected values (optimistic concurrency; null in set removes an attribute, null in expected means absent). batchPut and batchDelete split the items into the batches the target allows; they are not atomic.
  • Keys are 1 to 512 characters without /, \, #, ? and control characters; compose them with :, such as account:42. Attribute names start with a letter, followed by up to 63 letters, digits and underscores.
  • Attribute values are String, Long, Double, Boolean, List and Map. Whole numbers are read back as Long, others as Double, on every target. An item may have at most 400 KB.
  • Reads are strongly consistent on every target. There is no expiry (TTL).
  • access is READ (the default: get, query), WRITE (the writing operations) or READ_WRITE; the runtime refuses the others with KeyValueAccessDeniedException. On targets with identities, the generator also grants exactly these permissions on this table. Other failures throw KeyValueStoreException.
  • The generator creates the table once per name. Table names are 3 to 63 lowercase letters and digits, starting with a letter, unless the table is existing: one owned by another system, used under exactly this name. A table that your own Terraform creates goes into the local cloudhopper_table_names.

The target needs a runtime module for this, which the archetype adds. Which targets support @Table is listed in the support matrix.

Configuration​

Values that differ per deployment, such as resource names, endpoints or limits, are read with MicroProfile Config: @ConfigProperty on a parameter, or ConfigProvider.getConfig() in any code.

@Function(name = "report")
@ScheduledTrigger(cron = "0 6 * * *")
public void report(@ConfigProperty(name = "report.bucket") String bucket,
                   @ConfigProperty(name = "report.days", defaultValue = "7") int days,
                   @ConfigProperty(name = "report.cc") Optional<String> cc) {
    // ...
}
  • A property needs a name; there is no field or method name to derive it from.
  • Without a value and without defaultValue, the call fails with an exception that names the property and its environment variable. Optional<T> is empty instead.
  • Types: String, the primitive types and their wrappers, enums, List<T> (comma-separated, \, for a literal comma), and every class with a static of, valueOf or parse method or a constructor taking a String, e.g. Duration (PT30S) or URI.
  • Values are read on every call; the sources are read once per instance.

The deployment passes the values as environment variables: report.bucket becomes REPORT_BUCKET (every character other than a letter or digit becomes _, upper case). How to set them is described per target in Targets and what they support. System properties take precedence over environment variables, and META-INF/microprofile-config.properties in the function jar provides defaults for every target.

Cloudhopper ships a small implementation of the MicroProfile Config API with these three sources and the converters above; it keeps the runtime small and starts fast. It has no profiles, property expressions or config mapping. To use a complete implementation such as SmallRye Config instead, add it to the project; your own ConfigSource and Converter implementations registered through META-INF/services work with either.

Secrets​

Secrets, such as API keys or service account keys, are read like any other property; the code does not change:

@Function(name = "prices")
public PriceList prices(@ConfigProperty(name = "prices.gcp-credentials") String credentials) {
    // ...
}

The deployment decides that a property is a secret: instead of a value, it references a secret in the target's secret store. The value is not copied into the deployment (Terraform state, function environment); the function reads it at runtime and keeps it for the life of the instance, so a rotated secret reaches new instances. The function's identity may read exactly the secrets of the properties its functions read. A value set as an environment variable or system property takes precedence, e.g. for local runs and tests.

Which targets support secrets, and how to reference them, is described per target; see Configuration. With SnapStart, read secrets in the function call, not in a constructor or static initializer, so they are not part of the snapshot.

Identities and permissions​

Every function runs as an identity: the principal its permissions are granted to, an IAM role on AWS, a service account on GCP. By default, every function has an identity of its own, so a function gets only the permissions meant for it. Functions that need the same permissions can share one identity:

@Function(name = "connectAccount", identity = "connector")
@HttpTrigger(method = "POST", path = "/accounts")
public String connect(@RequestBody Account account) { ... }

@Function(name = "collectUsage", identity = "connector")
@ScheduledTrigger(cron = "0 3 * * *")
public void collect() { ... }

An identity name has up to 32 lowercase letters, digits and hyphens and starts with a letter. A function without identity uses its function name as the identity name. An explicit identity that is also the name of a function without identity is a build error, because both would silently run as one identity; to share it on purpose, declare the same identity on both functions.

The generator grants an identity logging and the permissions the triggers of its functions need, such as receiving from the function's queue. Nothing else: a function that reads another bucket, writes to a database or calls another account needs permissions from your own deployment configuration, attached to the identity. How to refer to the identity is described per target: AWS, GCP.

The name of an identity does not depend on the function names. Renaming a function keeps its identity, so policies elsewhere that refer to it, for example a role in another account that trusts it, keep working.

Targets that run the functions of a project in a shared application deploy one unit per identity: a function app on Azure, a Knative service with a service account of its own on Knative, a container on Scaleway. All units run the same package, and each answers only for the functions of its identity. On these targets the functions without an identity share one unit, the default one, instead of having one each.

Vendor extensions​

When you need a provider-specific setting that has no dedicated @Function attribute, attach it as an @Extension. Prefer the constants in ExtensionKeys over raw strings.

@Function(
    name = "hello",
    extensions = {
        @Extension(
            name = ExtensionKeys.Aws.Architecture.KEY,
            value = ExtensionKeys.Aws.Architecture.Values.ARM64)
    })
@HttpTrigger(method = "GET", path = "/hello/{name}")
public String hello(@PathParam String name) {
    return "hello " + name;
}

Only generators that declare support for a given extension key act on it; others ignore it.

KeyValuesTargetEffect
x-aws-architecture (ExtensionKeys.Aws.Architecture)arm64, x86_64aws-terraformCPU architecture of the Lambda function
x-aws-snapstart (ExtensionKeys.Aws.SnapStart)PublishedVersionsaws-terraformLambda SnapStart for shorter cold starts

What gets generated​

At build time the processor generates, per function:

  • a core <Class>_<method>_Handler that adapts your method to the runtime, plus a provider wrapper (e.g. an AWS Lambda entry point),
  • the infrastructure-as-code for the active generator (Terraform, OpenAPI, …),
  • metadata under META-INF/.

You never edit these — rerun the build and they are regenerated. See the Demo Project Guide for a full walk-through of the output, and the Deployment Config API for the annotation reference.
